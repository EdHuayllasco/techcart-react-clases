→
signal

abort()
la limpieza cancela el viaje
// Network, con StrictMode: monta y pide · desmonta y CANCELA · monta, pide y llega
GET /products  (canceled)   →   GET /products  200
El detalle fino: AbortError NO es un fallo. Es tu orden cumplida. El catch lo reconoce y lo deja pasar: ni estado de error ni respaldo — porque no pasó nada malo.

Seis piezas, un mapa

Las piezas del Router

BrowserRouter
envuelve todo en main.tsx: el que escucha la barra
Routes / Route
el mapa: qué dirección muestra qué página
Link
el enlace que no recarga: cambia la URL y la pantalla
useParams
la parte variable de la URL (:id) — llega como string
Outlet
"aquí va la página que toque": el Layout se escribe UNA vez
path="*"
el comodín: atrapa toda dirección desconocida → la 404
La arquitectura nueva: components/ = piezas reutilizables · pages/ = pantallas, una por dirección · App = el mapa. El estado se queda en App: las páginas van y vienen, el carrito permanece.

Errores frecuentes del Router

1 · <a href> en vez de Link
funciona… recargando la página entera: el estado muere, el carrito parpadea, la SPA deja de ser SPA
2 · olvidar BrowserRouter
todo lo del Router revienta al arrancar — y el mensaje de la consola te lo dice con nombre y apellido
3 · comparar useParams sin convertir
el id llega como string: '7' === 7 es falso → Number(id) antes del find
4 · F5 en producción da 404
en dev Vite resuelve las rutas; el servidor real necesita el rewrite de SPA — lo haremos al desplegar

El formulario controlado

form (estado)
un objeto, cuatro campos
→
value
pinta el input: lo que ves es lo que el estado dice
→
onChange
cada tecla vuelve al estado
⟲
form
el objeto DatosEnvio — copiar con spread, pisar un campo
tocados
qué campos visitó el usuario (onBlur) — esto SÍ es estado: no se puede calcular
errores
derivado: validar(form) corre en cada render — nada que sincronizar

Ese trío — form, tocados, errores derivados — es EL patrón de formularios de React.

Errores frecuentes de formularios

1 · value sin onChange
el input queda CONGELADO: React manda y nadie actualiza el estado — la consola además lo advierte
2 · errores en useState + efecto
el anti-efecto de la clase pasada, versión formularios: los errores se derivan, no se sincronizan
3 · validar solo con required / minLength
los atributos nativos son una red, pero el usuario merece mensajes tuyos, por campo
4 · olvidar preventDefault
la página recarga, el estado muere y el pedido nunca existió
