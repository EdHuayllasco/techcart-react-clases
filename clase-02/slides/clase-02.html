TecsupMASTERCLASS

La regla de oro de React

Las props no se tocan

// dentro de ProductCard:
producto.precio = 0;  // compila… y rompe la regla

Un componente lee sus props, las muestra, y nada más — la disciplina de las funciones puras de fundamentos. Si la tarjeta modifica el producto, App ya no puede confiar en su propio dato.

¿Y cómo se cambian los datos legalmente? Esa pregunta ES la clase 4 (useState). Hoy: se mira, no se toca.

El map de fundamentos (el de los Streams de Java) + las llaves de JSX: si la expresión devuelve un array de JSX, React pinta cada elemento.
Agregar un producto a datos.ts = agregar una tarjeta. Nadie vuelve a tocar este JSX.

Condicionales: ternario · && · return null

Qué pinta JSX — y la trampa del 0

false · null · undefined
JSX los traga en silencio — por eso el && funciona
0 · '' · textos · números
SÍ se pintan — y ahí está la trampa
{producto.stock && <p>…</p>}  // stock = 0 → pinta un 0 suelto
{producto.stock > 0 && producto.stock <= 5 && <p>¡Últimas unidades!</p>

Regla del proyecto: con números, la condición del && es una comparación explícita. Nunca el número pelado.
